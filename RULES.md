# Инженерные правила и стандарты качества (RULES.md)

Настоящий документ закрепляет обязательные правила разработки, безопасности и поддержки кода в репозитории **Maskani (`sogd-realty`)**.

---

## 1. Архитектура и организация кода

1. **Однонаправленный граф зависимостей**:
   - `src/app` / `src/middleware.ts` $\rightarrow$ `src/components/modules` $\rightarrow$ `src/components/ui` $\rightarrow$ `src/lib`.
   - Запрещены циклические зависимости и импорты из верхних слоёв в нижние.
2. **Чистота слоя `src/lib/`**:
   - Все расчёты (цены, рассрочка, ипотека, проверка доступности лотов, VAS-тарифы, рекламный скоринг, генерация SEO-маршрутов, хлебных крошек и JSON-LD) должны быть реализованы как чистые, тестируемые функции в `src/lib/`.
3. **Строгая типизация TypeScript**:
   - Режим `strict: true` обязателен.
   - Запрещено использование `any`, `@ts-ignore` и `@ts-expect-error`. Все входные параметры API и доменные структуры описываются явными интерфейсами.

---

## 2. Безопасность и валидация данных (Zero Client Trust)

1. **Сервер — единственный источник истины по ценам и статусам**:
   - В API бронирования (`POST /api/crm/lead-booking`), оплаты (`POST /api/payments/checkout`) и VAS (`POST /api/classifieds/vas`) клиентские суммы игнорируются или сверяются с серверным каталогом в сомони (`TJS`).
2. **Защита шахматки от несанкционированной блокировки**:
   - Отправка клиентской заявки на бронирование не переводит статус квартиры, паркинга или кладовой в `booked` или `sold`. Статус остаётся `available` до подтверждения менеджером в CRM.
3. **Защита персональных данных**:
   - Любая лид-форма обязана содержать неотмеченный по умолчанию (`false`) чекбокс согласия с политикой обработки персональных данных (`/privacy`).
4. **Защита от дублирования и спама**:
   - Серверные обработчики лидов контролируют окно дедупликации (10 секунд для одного номера телефона) и валидируют формат телефона (`+992`).

## 3. SEO и URL-архитектура (ТЗ v1.7)

1. **Единый источник правды**:
   - Все URL, canonical, hreflang, хлебные крошки, JSON-LD и элементы sitemap строятся строго через [`src/lib/seo/url-resolver.ts`](./src/lib/seo/url-resolver.ts).
2. **Правила языковых префиксов**:
   - RU: строго без префикса (например, `/dushanbe/arenda/kvartiry/...`). Использование `/ru/` категорически запрещено!
   - TG: `/tg/`
   - EN: `/en/`
   - У каждой языковой версии — собственный `self-canonical`. Взаимный `hreflang` включает `ru`, `tg`, `en` и `x-default` (RU).
3. **Реестр алиасов и 301-редиректов**:
   - При смене категории или slug старый URL обязан перенаправляться на актуальный канонический URL одним серверным 301-редиректом.
   - Запрещены цепочки редиректов (`A -> B -> C` обязаны моментально схлопываться в `A -> C`).
   - Запрещены циклические редиректы (`A -> A`).
4. **Партнёрские кабинеты и Zero Manual SEO**:
   - В кабинетах C2C, риэлторов, застройщиков и агентств запрещено размещать ручные поля для редактирования slug, H1, Meta Title, Meta Description, canonical, hreflang или JSON-LD. Партнёры вводят обычные бизнес-данные и выбирают категорию из утверждённого списка Super Admin.
5. **Безопасность пакетных операций**:
   - Работа с фактическими данными каталога. Запрещено создавать фиктивные записи в БД для тестирования масштабируемости (тесты 10 000+ записей проводятся исключительно в изолированных in-memory бенчмарках). Пакетные миграции обязаны поддерживать режим `DRY RUN`.

## 4. Тестирование и гигиена репозитория

1. **Обязательные проверки перед коммитом**:
   - Все тесты должны проходить: `npx tsx --test 'src/**/*.test.ts'` (**187+ тестов**).
   - Сборка должна завершаться успешно: `npm run build`.
2. **Синхронизация документации**:
   - Любое изменение публичных маршрутов, API или продуктовой логики сопровождается обновлением `README.md`, `ARCHITECTURE.md`, `TASKS.md`, `MEMORY.md` и AI-манифестов (`AGENTS.md`, `CLAUDE.md`, `CODEX.md`, `GEMINI.md`).

## 5. Мультиязычность (i18n) и валидация интерфейса (RU / TG / EN)

1. **Обязательная проверка всех трёх языков при любых правках UI**:
   - При любых изменениях визуальных компонентов (шапка `Header`, герой `Hero`, поисковый блок, карточки каталога, табы, фильтры, кнопки, модальные окна, выпадающие списки, футер) обязательна визуальная и логическая проверка во всех трёх поддерживаемых языках:
     - **Русский (`ru`)**
     - **Таджикский (`tg`)**
     - **Английский (`en`)**
2. **Нулевая терпимость к отсутствию переводов (No Russian Fallback in EN/TG)**:
   - В интерфейсе недопустимо использование двухъязычных хелперов `tDual(ru, tg)` без передачи третьего параметра для английского языка (`en`), либо использование типизированного словаря `t.nav.*` / `t.catalog.*`.
   - В английской версии (`en`) недопустимы остаточные русские слова («Карта», «Сравнение», «Все города», «Быстрый выбор:», «Найти ЖК»).
3. **Защита от переполнения верстки (Zero Layout Overflow) в таджикской версии**:
   - Таджикские термины на 30–50% длиннее (например, «Ширкатҳои сохтмонӣ», «Эълон гузоштан», «Воридшавӣ»).
   - Навигационные элементы обязаны использовать лаконичную терминологию (например, «Сохтмончиён» вместо «Ширкатҳои сохтмонӣ», «Иҷора ва тиҷорат» вместо многострочных названий) и адаптивные отступы (`px-1.5 xl:px-2.5`, `gap-0 xl:gap-0.5`).
   - Кнопка авторизации («Войти / Воридшавӣ / Sign In») и правые элементы управления обязаны иметь `shrink-0` и никогда не выталкиваться за пределы видимой области экрана на любых разрешениях (включая 1024px, 1280px, 1440px и мобильные).
4. **Отсутствие обрезки табов**:
   - Табы поиска и фильтрации не должны усекаться многоточием или накладываться друг на друга.
